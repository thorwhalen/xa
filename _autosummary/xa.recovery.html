xa.recovery¶

Bring back the sessions a shutdown killed, each as it was launched.

Two questions, answered from the transcripts alone (the processes are gone):

  1. Which sessions were alive at the last shutdown? When a machine shuts down, every running claude writes a final cost-state entry on its way out, so its transcript’s last write lands within seconds of the shutdown. sessions_alive_at_shutdown() returns the transcripts whose last write

    falls in [shutdown - window, boot). The shutdown time comes from last (last_shutdown_time()), the boot time from the kernel (boot_time()), and the record counts only when it belongs to this boot. Sessions resumed since then, running now, or already sitting in a tmux pane started with --resume <id> are never candidates, so applying twice resumes nothing twice. Headless runs (claude -p, the SDK) are skipped.

  2. How was each one launched? xa.claude_fs.launch_facts() reads one transcript for what claude --resume needs in order to come back the same:

    • the cwd: the first cwd whose slug is the transcript’s project folder. A session that cd-ed elsewhere records later cwds too, and resuming in the last one puts it in the wrong folder (thorwhalen/xa#23);

    • the permission mode: the last one recorded, plus whether bypass was ever reached (only a session started with the bypass flag can reach it);

    • the model of the last assistant turn, pinned only when its family differs from the account default’s (xa.claude_fs.resume_model()).

What a shutdown with no clean exit (a power cut, a kernel panic) leaves is not covered: no process wrote anything at the moment it died, so there is nothing to time it by.

xa.recovery.last_shutdown_time(*, before=None, run=<function _run>)[source]¶

Unix time of the shutdown that preceded the current boot, or None.

Read from last (minute resolution), newest record first: the current boot’s reboot line, then its shutdown. A second reboot line before any shutdown means this boot followed a crash (no clean shutdown), and an older record must not stand in for it. last -x reboot shutdown on Linux; macOS prints both kinds under last reboot.

Return type:

Optional[float]

xa.recovery.parse_last_stamp(text, *, before)[source]¶

The first Tue Nov 10 09:50-style stamp in text, as unix time.

last prints no year, so the year is the latest one that puts the stamp at or before before (local time).

>>> import time as t
>>> before = t.mktime((2026, 11, 10, 10, 0, 0, 0, 0, -1))
>>> ts = parse_last_stamp('shutdown time   Tue Nov 10 09:50', before=before)
>>> t.localtime(ts)[:5]
(2026, 11, 10, 9, 50)
Return type:

Optional[float]

xa.recovery.resume_all(candidates, *, claude_home=PosixPath('/home/runner/.claude'), claude_bin=None, tmux_bin=None, url_timeout_sec=120.0, auto_remote_control=True, permission_mode=None, euid=None)[source]¶

Resume every candidate in its own tmux session, each as it was launched.

All panes are launched first and only then waited on, so the whole batch takes about one url_timeout_sec, not one per session. A pane that comes up without a Remote Control URL gets the xa.revive verdict for what it is showing (needs_trust for a folder the account has not trusted, needs_login, …) in result.attention, rather than a hang. permission_mode overrides every candidate’s recorded mode ('': claude’s default).

Return type:

list[Resumed]

xa.recovery.sessions_alive_at_shutdown(*, claude_home=PosixPath('/home/runner/.claude'), window_sec=120.0, shutdown=None, boot=None, live_ids=None, tmux_bin=None)[source]¶

The sessions of claude_home whose last write fell at the last shutdown.

The window is [shutdown - window_sec, boot). With no shutdown record for this boot (a crash, or last unreadable), the anchor is the latest transcript write before boot instead, and the window is [anchor - window_sec, anchor]: the dry run says which was used. shutdown / boot / live_ids default to what this machine reports. Sessions in live_ids (running now) and headless runs are never candidates.

Return type:

ShutdownScan
